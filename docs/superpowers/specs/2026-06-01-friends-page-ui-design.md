# 友链页面 UI 优化设计

**日期**：2026-06-01  
**状态**：待实现  

## 背景与问题

当前友链页面在 `source/friends/index.md` 中直接内嵌 CSS，并用固定宽度的横向卡片展示链接。页面现在只有一个友链，但样式已经和全站自定义样式分散：

- 卡片宽度固定为 `320px`，移动端和未来多链接场景不够自然。
- 颜色和暗色模式没有完整接入 `source/_data/variables.styl` 的主题变量。
- 页面样式写在 Markdown 内，后续维护不如集中在 `source/_data/styles.styl` 清晰。
- 当前卡片的白底、阴影、圆头像更像通用资料卡，和博客正文页的阅读气质略有割裂。

## 目标

- 采用“编辑推荐式列表”方向，保留 NexT Gemini 正文页的安静阅读感。
- 将友链展示从固定卡片改为纵向推荐列表。
- 让样式接入现有主题变量，并补齐暗色模式、移动端、hover 和 focus 状态。
- 保持实现范围小，不改主题模板、不引入新依赖。

## 非目标

- 不做友链数据化配置文件。
- 不新增分类、筛选、搜索、申请友链表单。
- 不重做全站字体、导航、侧栏或页脚。
- 不把友链页做成营销式 hero 或卡片墙。

## 视觉设计

页面主体仍使用 Hexo/NexT 普通页面结构。友链内容区增加一段简短说明，下面是纵向列表。

每个友链条目包含：

- 头像：圆角方形，固定尺寸，使用真实头像图片；图片加载失败时由浏览器 alt 文本兜底。
- 名称：加粗，作为条目的主视觉锚点。
- 描述：一行到两行的简短说明，颜色弱于名称。
- 访问提示：右侧箭头或轻量视觉提示，仅表示可点击，不加入额外文案。

条目之间用轻分隔线组织，不再使用明显的独立白卡片。hover 时只做轻微位移、名称变色、箭头移动和边界/背景微调，避免过重阴影。

## 响应式规则

- 桌面端：列表宽度跟随正文容器，不再使用固定 `320px` 卡片宽度。
- 移动端：保持单列；头像、文字、箭头仍在一行内，必要时隐藏或弱化箭头，保证描述文本不挤压。
- 长描述：允许自然换行，行高保持可读；不依赖固定高度。

## 暗色模式

暗色模式使用现有变量：

- 背景跟随 `--content-bg-color` 或现有内容背景。
- 正文颜色跟随 `var(--text-color)`。
- 次级描述使用 `var(--blockquote-color)` 或接近的弱文本色。
- hover 强调色使用 `var(--link-hover-color)`。

不在友链页里硬编码一套独立暗色配色。

## 代码组织

修改范围控制在两个文件：

1. `source/friends/index.md`
   - 保留 front matter。
   - 移除内嵌 `<style>`。
   - 调整 HTML 结构为语义更清晰的列表容器和条目。

2. `source/_data/styles.styl`
   - 新增友链页样式段落。
   - 复用 `$myradius`、`$btn-default-bg`、`$btn-default-hover-bg` 等现有变量。
   - 使用 `+mobile()` 或媒体查询处理移动端。

不修改 `_config.next.yml`，因为菜单入口已经存在。

## 验证

实现后执行：

```bash
npm run build
```

并用本地预览检查：

```bash
npm run server -- --port 4000
```

需要在浏览器里确认：

- `/friends/` 桌面端布局正常。
- 移动视口下条目不溢出、不重叠。
- hover/focus 状态可见且不造成布局跳动。
- 暗色模式下文本、边框、头像背景仍可读。
