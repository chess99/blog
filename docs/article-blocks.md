# 文章内容模块

文章使用 `:::类型[标题]` 开始，以独占一行的 `:::` 结束。构建时生成语义 HTML，样式仅随使用模块的文章加载。代码围栏中的示例保持原样。标题、图注、代码与默认正文均按纯文本处理；叶节点的 `richText` 仅支持限定的粗体、行内代码与分段，不执行 HTML、模板或其他 Markdown。

现有模块包括 `flow`（线性流程）、`bars`（构成比例）、`decay`（时间衰减）、`score`（评分门槛）和 `diagram`（嵌套布局）。数据错误会使构建失败，避免遗漏内容。

## 嵌套图示与卡片

`diagram` 的块体为 JSON。它适合层次架构、分支结构、流程与卡片集合；内容完全在构建时生成，无 JavaScript 也可阅读。

````markdown
:::diagram[任务执行系统]
{
  "layout": "stack",
  "arrows": true,
  "items": [
    {"title": "任务入口", "text": "接收目标与工作环境", "tone": "accent"},
    {
      "layout": "row",
      "columns": 2,
      "title": "执行能力",
      "items": [
        {"title": "模型", "text": "根据反馈决定下一步", "chips": ["推理", "工具调用"]},
        {"title": "运行时", "badge": "执行层", "code": ["调用工具", "保存会话"], "tone": "muted"}
      ]
    },
    {"title": "结果", "text": "核验任务并生成报告"}
  ],
  "note": "箭头表示执行顺序。"
}
:::
````

### 组合节点

根节点必须是组合节点。组合节点也可以放在另一个组合节点的 `items` 中。

| 字段 | 含义 |
| --- | --- |
| `layout` | 必填，`stack` 纵排、`row` 横排、`grid` 网格 |
| `items` | 必填，1–32 个组合节点或叶节点，按阅读顺序填写 |
| `columns` | 可选，1–4 的整数；横排或网格的列数，默认取节点数与 3 的较小值 |
| `arrows` | 可选布尔值，默认关闭；纵排显示下箭头，横排或网格宽屏显示右箭头 |
| `connectors` | 可选字符串数组，仅在 `arrows:true` 时可用，长度必须为 `items` 数量减 1；按顺序指定相邻节点的连接符 |
| `title`、`text` | 可选的组标题与说明 |
| `badge` | 可选的组状态，与组标题在同一行 |
| `note` | 可选的组后图注 |
| `variant` | 可选的表现结构，见下表；省略时保留原有通用布局 |
| `surface` | 可选，`none` 无框无底、`outline` 描边、`fill` 轻填充；显式设置优先于默认表面 |
| `align` | 可选，`left` 或 `center`，可在子节点覆盖 |
| `showTitle` | 仅根节点可用，默认 `true`；设为 `false` 时隐藏额外图题，仍保留辅助阅读所需的图注 |

连接符只支持 `↓`、`→`、`↕`、`↔`、`+`、`=`、`⑂`。其中 `⑂` 是分支 SVG 图标的配置标记，页面不直接显示该字符。例如两个节点设置 `"connectors": ["+"]` 表示相加，三层架构设置 `"connectors": ["↕", "↕"]` 表示双向关系。连接符为装饰元素，不参与辅助阅读内容；关系含义也应在正文或节点文案中说明。

每组按自己的可用宽度布局；不足 560px 时，横排和网格改为纵排，默认箭头随之朝下。显式指定的连接符保持原符号，包括双向箭头、加号和等号。多行网格适合无顺序的集合，连续流程优先使用 `stack` 或单行 `row`。整张图最多 8 层、160 个节点。

新 `panel` 内部设置了 `surface:none` 的无框嵌套组，宽度达到 300px 时即可按 `columns` 保留并列关系，例如两列投影视图或三列子任务；单格内容仍自然换行。此规则不作用于根级 `comparison`，也不改变未使用新表现结构的通用图示的 560px 阈值。居中的短说明使用均衡换行，减少窄屏上单个字落入最后一行的情况。

### 表现结构

布局和表面分开配置，避免将不同内容强制画成同一种卡片。

| `variant` | 适用结构 |
| --- | --- |
| `panel` | 单个外框中的架构、等式或分叉关系；内部节点可设 `surface:none`，只为关键结果保留描边 |
| `timeline` | 左侧竖条的顺序步骤；条目没有独立卡框，`tone:accent` 只将重点条目的竖条改为绿色 |
| `numbered` | 独立的左侧圆形编号栏和右侧紧凑内容条；使用叶节点 `badge` 作为编号，未设置时自动编号；箭头对齐编号栏 |
| `tree` | 有内标题与状态的任务树，步骤略作缩进，工具可用实心标签，最终结果可无框居中 |
| `comparison` | 各列分别承担外框的对比面板，外层不再重复套框；通常配合 `layout:grid` 和 `columns:2` |
| `list` | 由图标、正文和分隔线组织的条目，不为每条增加卡框 |

`timeline`、`numbered`、`tree`、`list` 使用 `layout:stack`。新表现结构的强调色为绿色，连接符使用正文次级色；未设置 `variant` 的通用图示保留原有蓝色强调。

### 叶节点

| 字段 | 含义 |
| --- | --- |
| `title` | 可选标题 |
| `text` | 可选正文，字符串中的 `\n` 显示为换行 |
| `richText` | 可选的限定富文本正文，与 `text` 互斥；只识别 `**粗体**`、反引号包裹的行内代码，双换行拆为段落；其余内容均转义 |
| `chips` | 可选，1–32 个非空字符串，显示为标签集合 |
| `chipsColumns` | 可选，1–4 整数，将 `chips` 排成固定列数的网格；不设置时自动换行 |
| `chipsStyle` | 可选，`filled` 实心标签或 `outline` 描边标签；需要同时提供 `chips` |
| `code` | 可选，1–32 个非空字符串，按换行连接为代码文本 |
| `tone` | 可选，`plain`（默认）、`accent` 或 `muted` |
| `badge` | 可选状态，默认与标题左右同行；编号流程中作为前导编号 |
| `badgePosition` | 可选，`header`（默认）或 `after`；后者将状态放在说明之后，需要 `badge` |
| `surface`、`align` | 与组合节点相同，可独立控制节点表面和对齐 |
| `icon` | 可选装饰图标，白名单为 `brain`、`laptop`、`bot`、`terminal`、`code`、`check` |

叶节点至少包含 `title`、`text`、`richText`、`chips`、`code` 中的一项，只有状态或图标的空节点无效。所有字符串必须非空；未知字段、错误类型和不完整布局会报错。`richText` 不解析嵌套标记，也不接受原始 HTML；用于有明确行内格式的正文即可。

## 图片组、资源卡与引用

文章 front matter 设置 `rich_content: true`，可按需加载 `article-rich-content.css`：

- `.article-image-group`：图片链接组，桌面三列、手机横向滑动；配图仍引用 `source/images/<slug>/` 的本地发布副本。
- `.article-resource-list` / `.article-resource-card`：保留段落、图片和外链的资源卡片。
- `.article-citation`：包含可直接打开来源的 `.article-citation-label` 链接，以及列出全部来源的 `.article-citation-popup`。鼠标停留或键盘焦点进入时展开；手机显示在屏幕底部。
- 四列及以上的 Markdown 表格会生成可聚焦的横向滚动区域，避免手机上把产品名与正文挤成单字列；普通表格与代码高亮不变。

手写 HTML 应放在 Hexo 的 `{% raw %}` / `{% endraw %}` 标签之间。公式使用 `mathjax: true` 并按 NexT 的数学语法书写。只改构建插件时，需先 `npm run clean` 再构建，以刷新 Hexo 的文章缓存；本地服务也需重启才能加载新的插件。

## 验证

运行 `npm test` 检查解析、嵌套、转义、代码围栏保留及资源加载。修改布局后，还需通过本地预览检查宽窄屏、深浅色、长内容和嵌套布局。
