# Claude Code 终极使用技巧指南：从入门效率到高阶自动化全攻略

我们身边用Claude Code的人越来越多，但绝大多数人只用到了它10%的能力——有人已经能用多Agent并行跑全流程开发，有人还在为每次换行、每步命令确认发愁；有人靠一行命令救回跑偏一下午的开发，有人还不知道双击Esc就能回退代码。

Claude Code的更新速度快到离谱，上班、睡觉都在迭代，大量实用功能藏在更新日志、开发团队动态里，官方文档甚至都来不及同步。这份指南基于最新版本的CHANGELOG和官方最佳实践，整理了从入门到高阶的全场景技巧，不止是命令列表，更是能直接落地的提效方案，帮你把Claude Code从「代码助手」用成「专属研发团队」。

## 一、会话生命周期管理：解决上下文污染、回退、分叉的核心技巧

这部分是所有开发场景的基础，能解决90%人遇到的「对话跑偏」「上下文乱了」「写一半想重来」的痛点。

### 1. /btw：长任务不中断的临时查询神器

这是2025年3月新增的功能，也是公认的「用了就回不去」的神级命令，完美解决**上下文污染**的世纪难题。

- **核心用法**：在Claude执行长任务（比如重构大模块、全量代码扫描）的过程中，直接输入`/btw 你的问题`，就能发起一个并行子查询，完全不中断主任务的执行。
- **隐藏细节**：
  - 查询结果不会写入主对话历史，回答完按空格/回车就能直接消除，会话干干净净；
  - 复用当前会话的Prompt缓存，几乎不消耗额外token；
  - 最新版本已修复「粘贴文本不生效」「流式响应中调用返回主Agent输出」的问题，稳定性拉满。
- **适用场景**：开发中途突然想查文件路径、确认配置参数、核对接口文档，不用等任务跑完，也不会打断Claude的开发节奏。

### 2. /rewind（双击Esc）：代码和对话的「后悔药」

不用再含泪敲`git reset`，这个命令能让你精准回退到会话的任意节点，是新手最该掌握的第一个命令。

- **核心用法**：
  - 快捷键：双击`Esc`一键触发回退菜单；
  - 手动输入`/rewind`，会列出会话的所有历史节点，选择对应节点即可回退。
- **核心能力（绝大多数人不知道）**：支持**代码和对话分离回退**，提供4种精准选项：
  1. 回退代码和对话（完全回到该节点）
  2. 回退对话但保留代码（保留开发成果，重新调整需求）
  3. 回退代码但保留对话（代码写废了，让Claude基于之前的讨论换方案，不用重新解释需求）
  4. 压缩该节点之后的对话，释放上下文token空间
- **最佳实践**：做技术方案实验时，试一种写法不行，就回退代码保留对话，Claude会自动规避踩过的坑，效率比重新写prompt高10倍。

### 3. /branch（原/fork）：会话的「平行宇宙」

想试两种不同的实现方案，又不想丢掉当前的会话进度？这个命令就是最优解。

- **核心用法**：输入`/branch`，会基于当前会话分叉出一个全新的独立会话，原会话的所有上下文、代码状态完全保留，不受新会话的任何影响。`/fork`仍可作为别名使用，会自动跳转至`/branch`。
- **隐藏用法**：配合`--session-id`参数，启动时直接指定分叉会话的ID，方便后续恢复；配合`/resume`可一键找回所有分叉的会话。
- **适用场景**：
  - 方案A/B测试：比如一个功能想试React和Vue两种实现，分叉两个会话并行开发，最后选效果好的；
  - 风险操作：比如重构核心模块、修改数据库表结构，先分叉会话测试，没问题再合并到主会话。

### 4. 会话恢复与管理：告别「重启就找不到之前的对话」

绝大多数人重启Claude Code就只能从头开始，而这几个命令能让你无缝衔接之前的工作。

- **/rename & --name启动参数**
  - 输入`/rename 会话名称`，给当前会话起一个可检索的名字（比如`feat-用户登录-oauth`），不用再靠默认的会话ID找历史；
  - 启动时加`--name 名称`参数，直接创建命名会话，后续一键恢复。
- **/resume 会话恢复全家桶**
  - 基础用法：`claude --resume` 打开会话选择器，一键回到之前的任意会话；
  - 精准恢复：`claude --resume 会话名称/ID`，直接启动并恢复指定会话；
  - 开发神器：`claude --resume --from-pr PR号/PR链接`，直接恢复和该PR关联的会话，多人协作、迭代PR需求时效率拉满。
- **/continue**：`claude --continue` 直接恢复当前目录下最近的一次会话，下班没干完的活，上班一条命令就能接着聊。

## 二、开发提效核心命令：让编码效率翻倍的隐藏指令

这些命令能精准解决「AI写的代码冗余」「模型用不对浪费额度」「改完代码才发现方案错了」的核心痛点。

### 1. /model opusplan：Pro订阅用户的额度神器

这是正儿八经的隐藏命令，直接在`/model`选择器里根本找不到，却是20刀Pro订阅用户的「省钱+提效」最优解。

- **核心能力**：开启后，Claude会在**复杂规划、架构设计**时自动使用Opus 4.6（深度推理能力拉满），在**具体代码实现、单文件修改**时自动切换到Sonnet 4.6（速度快、额度消耗低）。
- **核心价值**：Pro用户的Opus额度非常有限，全程用Opus很容易写到一半就被限速，而这个模式完美拆分了「规划」和「执行」的模型需求——用Opus做最擅长的架构设计，用Sonnet做它能胜任的代码落地，兼顾效果、速度和成本。
- **进阶用法**：除了`opusplan`，还有`haikuplan`模式，适合简单的工具类项目，用Sonnet做规划，Haiku做执行，速度更快、成本更低。

### 2. /effort：精准控制模型的思考深度

很多人不知道，Claude的响应速度、思考深度、token消耗，都能通过这个命令一键控制，不用再靠「think harder」「ultrathink」这类提示词。

- **核心用法**：
  - `/effort low`：低努力模式，响应速度最快，适合简单的代码修改、语法修复、文件查询，token消耗最低；
  - `/effort medium`：默认模式，平衡速度和深度，适合绝大多数日常开发场景；
  - `/effort high`：高努力模式，深度推理，适合复杂架构设计、安全审计、疑难bug修复；
  - `/effort auto`：恢复自动模式，Claude会根据任务复杂度自动调整。
- **隐藏细节**：
  - 可以在Claude响应的过程中实时修改，不用等任务结束；
  - 支持写在Skill、Slash命令、Agent的frontmatter里，调用时自动切换对应的努力程度，比如代码审查的Skill默认用high，文件查询的Skill默认用low。

### 3. /simplify：三合一的AI代码审查工具

这是2025年2月底内置的Skill，比传统的`/review`命令好用10倍，也是很多资深开发者每次开发完必跑的命令。

- **核心能力**：输入`/simplify`后，Claude会同时启动3个平行Agent，分别从**代码复用性、代码质量、运行效率**三个维度，全量审查你当前的代码改动，最后汇总出可落地的优化建议。
- **进阶用法**：`/simplify 文件路径`，指定审查特定文件，不用全量扫描；配合`/batch`命令，可批量审查多个文件的改动。
- **最佳实践**：每次和Claude多轮开发、完成大的功能更新后，顺手跑一遍`/simplify`，能精准揪出AI写的代码里的冗余import、重复逻辑、可简化的写法，相当于3个资深同事同时帮你做Code Review。

### 4. /plan：先谋后动，避免开发到一半跑偏

很多人用Claude写代码翻车，核心原因是「上来就让它写，写到一半发现方案错了」，而`/plan`命令就是解决这个问题的最优解。

- **核心用法**：
  - 基础用法：`/plan 你的需求描述`，比如`/plan 实现带短信验证码的用户注册功能`，Claude会直接进入计划模式，先输出完整的开发方案，不会直接写代码；
  - 进阶操作：Claude输出计划后，按`Ctrl+G`可以直接在外部编辑器里修改计划，也可以在VSCode里打开完整的Markdown预览，添加评论、修改细节，确认无误后再让Claude执行。
- **隐藏细节**：计划接受后，Claude会自动用计划内容给会话命名，方便后续恢复；可通过`"showClearContextOnPlanAccept": true`配置，恢复计划接受时的「清除上下文」选项。
- **官方最佳实践**：复杂任务一定要先让Claude出计划，你确认方案没问题后，再让它执行，能减少80%的代码回退、需求跑偏的问题。

### 5. /compact：手动释放上下文空间，告别token溢出

长会话写着写着就提示「上下文已满」？不用开新会话，这个命令能帮你压缩历史，保留核心信息。

- **核心用法**：
  - 基础用法：`/compact`，全量压缩当前会话的历史对话，把多轮对话整合成核心摘要，释放大量token空间；
  - 精准压缩：选择会话里的某条消息，使用「从这里开始总结」，只压缩该节点之后的内容，保留核心需求上下文；
- **隐藏细节**：压缩时会自动保留图片、PDF、二进制文件的引用，不会导致上下文丢失；支持`PostCompact`钩子，压缩完成后自动触发自定义操作，比如自动备份会话、生成开发日志。

## 三、自动化与多Agent并行：把重复工作全交给AI

Claude Code最强大的能力，从来不是「替你写一行代码」，而是「替你跑完整套工作流」，这部分技巧能让你彻底从重复劳动里解放出来。

### 1. /loop：定时重复任务的自动化神器

这是最新版本新增的功能，完美解决「需要盯着服务状态、定时检查部署结果」的痛点，不用自己写crontab脚本。

- **核心用法**：`/loop 时间间隔 要执行的任务`，时间单位支持`s/m/h/d`（秒/分钟/小时/天），比如：
  - `/loop 30s 检查本地3000端口的服务是否正常运行`
  - `/loop 5m 拉取一次线上部署日志，检查是否有报错`
  - `/loop 1h 同步一次数据库备份到对象存储`
- **隐藏细节**：
  - 输入`/loop list`查看当前运行的所有循环任务，`/loop stop 任务ID`停止指定任务；
  - 循环任务默认3天后自动过期，避免被遗忘的任务长期运行，桌面版可配置永久运行；
  - 任务结果会直接写入会话上下文，Claude可以基于结果自动做后续操作，比如检查到服务宕机，自动执行重启命令。

### 2. 后台任务与Agent管理：不阻塞会话的并行执行

很多人不知道，Claude Code支持把任务放到后台运行，你可以继续写代码、提新需求，不用等任务跑完。

- **核心快捷键与命令**：
  - `Ctrl+B`：把当前运行的前台任务（比如启动开发服务、跑单元测试、大文件扫描）后台化，不阻塞主会话的操作；
  - 两下`Ctrl+F`：一键杀死所有后台运行的Agent和任务，避免失控的进程占用资源；
  - `/agents`：列出所有配置的自定义Agent，查看运行状态、管理生命周期。
- **进阶用法**：在自定义Agent的配置里，添加`background: true`，让这个Agent被调用时默认在后台运行，比如写一个「测试用例生成Agent」，调用后自动后台跑，生成完再通知你，不影响主开发流程。

### 3. Agent Teams：多Agent并行开发，打造你的专属研发团队

这是Claude Code的实验性王炸功能，能让多个AI Agent分工协作，并行完成复杂项目，效率直接翻倍。

- **开启方式**：设置环境变量`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`，即可启用多Agent团队功能。
- **核心能力**：你可以给不同的Agent分配不同的角色，比如：
  - 架构师Agent：负责技术方案设计、模块拆分
  - 前端开发Agent：负责页面、组件开发
  - 后端开发Agent：负责接口、数据库逻辑开发
  - 测试工程师Agent：负责单元测试、集成测试编写
  - 运维Agent：负责部署、配置、监控检查
- **隐藏细节**：团队内的Agent会自动共享上下文、同步进度，继承主会话的模型和权限配置；支持`TeammateIdle`、`TaskCompleted`钩子，自定义团队协作的自动化逻辑，比如测试Agent跑完用例，自动触发运维Agent部署到测试环境。
- **最佳实践**：中大型项目开发时，先让主Agent拆分模块和角色，再启动Agent Team并行开发，比单会话串行开发效率提升3-5倍。

### 4. 自定义Skill与Slash命令：把重复操作封装成一键指令

凡是你每天都要重复做的操作，都应该封装成自定义Skill或Slash命令，这是资深用户和新手的核心区别。

- **自定义Slash命令**：
  - 项目级命令：放在项目的`.claude/commands/`目录下，提交到git后，团队所有成员都能使用；
  - 个人级命令：放在`~/.claude/commands/`目录下，所有项目都能调用；
  - 极简示例：创建`.claude/commands/test.md`，内容如下，使用时输入`/test`就能一键运行所有单元测试。
    ```markdown
    ---
    description: 运行项目所有单元测试并生成覆盖率报告
    argument-hint: [可选: 测试文件路径]
    ---

    运行项目的所有单元测试，生成覆盖率报告。
    如果提供了$ARGUMENTS，只运行指定的测试文件。
    ```
- **自定义Skill**：
  - 支持热重载：修改`.claude/skills/`目录下的Skill文件，不用重启会话，立即生效；
  - 支持隔离运行：添加`context: fork`到frontmatter，Skill会在分叉的子Agent里运行，不污染主会话上下文；
  - 支持能力锁定：添加`effort: high`、`model: opus`到frontmatter，固定Skill运行时的模型和努力程度，保证执行效果稳定。

## 四、跨端与远程协同：随时随地无缝编码的秘诀

Claude Code不止能在本地终端用，这些技巧能让你在手机、浏览器、其他电脑上，无缝衔接本地的开发环境，真正实现「随时随地Vibe Coding」。

### 1. /remote-control（/rc）：手机也能操控本地开发环境

这是2025年2月底新增的功能，也是远程办公、临时改bug的神器，安全性和便捷性拉满。

- **核心用法**：在终端里输入`/rc`或完整的`/remote-control`，Claude会生成一个专属URL，用手机打开这个链接，就能直接操控本地的Claude Code会话。
- **核心优势**：
  - 全量同步：手机和终端的会话完全实时同步，两边可以交替操作，对话历史、代码状态完全一致；
  - 安全可控：代码始终在你的本地电脑上运行，手机只是一个远程操作窗口，你的文件系统、MCP服务器、项目配置都不会离开本地；
  - 自定义配置：输入`/rc 会话名称`，给远程会话设置自定义名称，手机上能清晰区分不同的开发项目。
- **隐藏细节**：`/exit`退出远程控制时，会自动归档会话；企业版支持配置远程控制的权限限制，比如只读模式、禁止高危命令执行。

### 2. /teleport：会话跨设备无缝传送

在公司电脑上写了一半的代码，回家想接着写？不用传文件、不用同步会话，这个命令一键搞定。

- **核心用法**：claude.ai订阅用户可直接使用，输入`/teleport`，就能把本地的当前会话，传送到claude.ai网页端；也可以在网页端把会话teleport到本地电脑，无缝衔接开发进度。
- **进阶用法**：配合`--session-id`参数，指定要传送的会话ID，不用打开会话就能跨设备同步；配合`--resume`，在新设备上一键恢复传送过来的会话。

### 3. VSCode深度集成：把Claude Code搬进编辑器

绝大多数人只在终端里用Claude Code，却不知道它的VSCode插件有超多隐藏能力，能和你的开发流程深度融合。

- **核心隐藏功能**：
  - 可编程URI唤醒：`vscode://anthropic.claude-code/open`，可以直接用脚本、快捷键打开新的Claude Code标签，还能带`prompt`和`session`参数，一键启动预设好的开发会话；
  - 原生MCP管理：在VSCode的聊天面板里输入`/mcp`，直接打开图形化的MCP服务器管理界面，不用去终端输命令，就能启用/禁用服务器、管理OAuth认证、重连服务；
  - 会话全量管理：VSCode活动栏会显示Claude的图标，点开就能看到所有的历史会话，一键切换，不用记会话名称和ID；
  - Python虚拟环境自动激活：插件会自动识别项目的Python虚拟环境，确保pip、python命令用的是项目里的解释器，不会出现环境不一致的问题。

### 4. --worktree（-w）：隔离开发，不污染主分支

实验性的代码修改、不确定的方案测试，最怕把主分支的代码搞乱，这个启动参数能完美解决这个问题。

- **核心用法**：启动时输入`claude -w`或`claude --worktree`，Claude会自动创建一个隔离的git工作树，所有的代码修改、文件增删、分支操作，都在这个隔离的工作树里进行，完全不会影响主分支的代码。
- **进阶用法**：
  - 配合`worktree.sparsePaths`配置，在大型 monorepo 里，只检出你需要的目录，大幅提升启动速度；
  - 在自定义Agent的配置里，添加`isolation: worktree`，让子Agent运行时自动创建隔离工作树，就算代码写崩了，也不会影响主项目。

## 五、终端快捷键大全：手不离键盘的极致效率

不用鼠标、不用频繁切换窗口，这些快捷键能让你在Claude Code里的操作效率直接拉满，也是资深用户的必备技能。

### 1. 基础编辑与会话快捷键

| 快捷键                      | 核心功能                     | 隐藏细节                                                                         |
| --------------------------- | ---------------------------- | -------------------------------------------------------------------------------- |

### 2. Bash模式（!）专属技巧

很多人不知道，输入`!`就能直接进入bash模式，不用每次都跟Claude说「运行xx命令」，终端操作效率直接拉满。

- 核心快捷键：
  - `Tab`：bash模式下自动补全历史命令，和终端里的Tab补全体验一致；
  - `Ctrl+B`：把运行中的bash命令后台化，比如启动开发服务器时，后台化之后Claude可以继续写代码，不用等服务启动完成。
- 隐藏福利：Claude Code内置了大量自动免确认的bash命令，包括`lsof`、`pgrep`、`tput`、`ss`、`fd`、`git`相关的只读命令等，不用每次都点「允许」，大幅减少操作步骤。

### 3. Vim模式全量快捷键

如果你是Vim用户，Claude Code内置了完整的Vim motions，完全不用适应新的操作习惯。

- 开启方式：输入`/vim`一键开启/关闭Vim模式；
- 核心支持的操作：
  - 基础移动：`h/j/k/l`、`0/$`、`gg/G`；
  - 字符搜索：`f/F/t/T`，用`;`和`,`重复上一次搜索；
  - 复制粘贴：`yy/Y`复制整行，`p/P`粘贴；
  - 文本对象：`iw/aw`（单词）、`i"/a"`（引号）、`i(/a(`（括号）、`i{/a{`（大括号）等；
  - 缩进编辑：`>>`缩进、`<<`取消缩进、`J`合并行；
  - 撤销重做：`u`撤销、`Ctrl+R`重做。

## 六、上下文与内存管理：彻底告别token溢出、对话跑偏

长会话最容易遇到的两个问题：一是上下文满了，开新会话又要重新解释需求；二是对话多了，Claude开始忘记之前的约定，写的代码越来越跑偏。这部分技巧能彻底解决这些问题。

### 1. /context：上下文健康度自查与优化

这是每个长会话都必跑的命令，能帮你精准定位上下文占用的元凶，给出可落地的优化建议。

- **核心用法**：直接输入`/context`，Claude会生成一份完整的上下文分析报告，包括：
  - 当前上下文的使用百分比、剩余token空间；
  - 哪些工具、文件引用、内存内容占用了大量token；
  - 上下文臃肿的核心原因，以及对应的优化建议（比如压缩历史、移除不必要的文件引用、合并重复内容）。
- **进阶用法**：可以在status line里配置显示上下文使用百分比，实时监控上下文健康度，快满了就及时压缩，避免写到一半被中断。

### 2. /memory：让Claude真正「记住」你的习惯

很多人抱怨Claude「记不住事」，每次都要重复说编码规范、项目架构、个人习惯，而自动内存功能就是解决这个问题的。

- **核心能力**：Claude会自动把会话里有用的上下文，存到auto-memory里，比如项目的目录结构、你的编码规范、常用的技术栈、踩过的坑，后续的会话会自动读取这些记忆，不用你重复解释。
- **手动管理**：
  - 输入`/memory`，直接打开内存编辑界面，查看、修改、删除所有的自动内存内容；
  - 配置`autoMemoryDirectory`，自定义内存文件的存储目录，团队项目可以把内存文件提交到git里，共享给所有团队成员，让整个团队的Claude Code都遵循统一的项目规范。

### 3. CLAUDE.md与规则文件：项目级的持久化上下文

这是官方最推荐的最佳实践，能让Claude Code一启动，就知道你的项目规范、架构约定、开发流程，从根源上避免对话跑偏。

- **CLAUDE.md核心用法**：在项目根目录创建`CLAUDE.md`文件，写入项目的架构说明、编码规范、构建命令、提交规范、注意事项等内容，Claude Code启动时会自动加载这个文件，全程遵循里面的约定。
  - 进阶技巧：文件里支持`@include 路径/文件.md`指令，导入其他的markdown文件，比如把编码规范、架构设计、测试规范拆分成单独的文件，用include指令统一导入，方便维护。
- **.claude/rules/ 目录进阶**：
  - 在这个目录下创建markdown规则文件，支持`paths` frontmatter，实现「特定目录下生效特定规则」，比如前端目录加载前端React编码规范，后端目录加载Java开发规范；
  - 规则文件支持`if`条件判断，比如只有在生产环境部署时，才加载安全检查相关的规则。

### 4. 上下文优化核心技巧

1. 大文件用`@-mention`引用，不要直接粘贴内容，Claude会按需读取文件内容，不会全量加载到上下文，大幅节省token；
2. 超过50K的工具输出，会自动保存到磁盘，只在上下文里放文件引用，不用手动处理，Claude会自动读取；
3. 临时查询、无关问题，一律用`/btw`处理，绝对不要写入主会话历史，从根源上避免上下文污染；
4. 定期用`/compact`压缩会话历史，默认上下文占用到80%时会自动压缩，也可以手动调整阈值。

## 七、权限与安全配置：告别重复确认，兼顾效率与安全

很多人用Claude Code，一半的时间都在点「允许执行命令」，而合理的权限配置，能在保证安全的前提下，让Claude全自动干活，不用你每步都确认。

### 1. /permissions：权限规则全量管理

这个命令能让你统一管理所有的权限规则，告别重复的确认弹窗。

- **核心用法**：输入`/permissions`，打开权限管理界面，支持搜索过滤规则，用Tab/箭头键切换Workspace、User、Session三个级别的标签，分别对应「项目级」「全局用户级」「当前会话级」的规则。
- **通配符规则（核心提效技巧）**：权限规则支持完整的通配符匹配，不用一条一条加规则，比如：
  - `Bash(npm *)`：允许所有npm开头的命令，比如npm install、npm run dev等；
  - `Bash(git * main)`：允许所有和main分支相关的git命令；
  - `Bash(python *)`：允许所有python相关的命令；
  - `deny: ["mcp__servername/*"]`：禁用某个MCP服务器的所有工具。
- **最佳实践**：把常用的、安全的命令，配置成User级别的允许规则，所有项目都生效；项目专属的命令，配置成Workspace级别的规则，团队成员共享，不用每个人都重复配置。

### 2. 权限模式配置：按需选择自动化程度

Claude Code提供了4种核心权限模式，适配不同的场景，你可以根据任务的风险等级灵活切换。
| 权限模式 | 核心能力 | 适用场景 |
|----------|----------|----------|
| acceptEdits | 自动接受所有文件编辑操作，不用每次确认 | 信任的项目、日常开发、简单的代码修改 |
| plan模式 | 先出完整计划，你确认后，再自动执行所有操作 | 复杂功能开发、多文件改动、架构调整 |
| bypassPermissions | 绕过所有权限确认，全自动执行所有命令和文件操作 | 完全信任的环境、自动化脚本、非交互模式（注意：有高危风险，企业版可禁用） |
| 手动确认模式 | 所有操作都需要你手动确认 | 陌生项目、高危操作、安全敏感的场景 |

### 3. 沙箱模式Sandbox：安全兜底的必备功能

对于不信任的任务、陌生的仓库，开启沙箱模式，能彻底避免Claude执行的命令修改你的系统文件、泄露敏感数据。

- **开启方式**：输入`/sandbox`打开沙箱配置界面，开启`sandbox.enabled`即可启用，目前支持Linux和macOS系统。
- **核心配置**：
  - `sandbox.allowRead`/`sandbox.allowWrite`：配置允许Claude读写的目录，除此之外的目录一律禁止访问；
  - `sandbox.enableWeakerNetworkIsolation`：macOS专属配置，开启后允许Go程序（比如gh、gcloud、terraform）在沙箱里正常访问网络；
  - `sandbox.excludedCommands`：配置不需要沙箱隔离的命令，比如git只读命令。
- **安全保障**：开启沙箱后，如果依赖缺失，会显示明确的启动警告，不会静默禁用沙箱，彻底避免安全漏洞。

### 4. Hooks钩子：自动化权限审批与工作流

Hooks是Claude Code的高阶能力，能让你在会话的整个生命周期里，插入自定义的自动化脚本，实现权限自动审批、会话自动备份、代码自动格式化等能力。

- **核心常用钩子**：
  - `PreToolUse`：工具调用前触发，最常用的场景是自动审批权限，比如写个脚本，自动允许git、npm相关的安全命令，拒绝rm -rf /、格式化系统盘之类的高危命令；
  - `SessionStart`/`SessionEnd`：会话启动/结束时触发，比如会话结束时自动备份会话到git、生成开发日志；
  - `PostCompact`：会话压缩后触发，比如压缩后自动清理临时文件、同步内存到团队仓库；
  - `ConfigChange`：配置文件修改时触发，企业版可用于安全审计，拦截违规的配置修改。
- **进阶配置**：每个钩子都可以自定义超时时间，默认10分钟，也可以通过环境变量配置全局超时时间。

## 八、插件与MCP生态进阶：解锁Claude Code的无限能力

Claude Code的核心竞争力，就是它的插件和MCP（Model Context Protocol）生态，能让它直接对接GitHub、Slack、数据库、云服务、各种API，从「代码助手」变成「全链路自动化平台」。

### 1. /plugin 命令全攻略

- **核心常用命令**：
  - `/plugin install 插件地址`：安装插件，支持git、npm源，还能pin到特定的commit、分支、标签，比如`/plugin install owner/repo#v1.0.0`，保证插件版本稳定；
  - `/plugin enable/disable 插件名称`：启用/禁用插件，项目级别的插件会修改`.claude/settings.local.json`，不会影响团队其他成员；
  - `/plugin marketplace`：打开插件市场，浏览、安装官方和第三方插件；`/plugin marketplace add 地址`，添加企业内部的私有插件市场；
  - `/plugin validate`：验证插件的结构和配置，开发插件时必备，能检查出Skill、Agent、Hooks的配置错误、语法问题；
  - `/reload-plugins`：重新加载所有插件，修改插件配置、更新插件后，不用重启会话，立即生效。
- **团队协作技巧**：配置`CLAUDE_CODE_PLUGIN_SEED_DIR`环境变量，设置插件的种子目录，Claude启动时会自动安装目录里的所有插件，团队项目可以统一配置，所有人都用一样的插件版本，避免环境不一致的问题。

### 2. MCP进阶用法

MCP是让Claude对接外部系统的核心协议，掌握这些技巧，能让Claude直接操控你用的所有工具和服务。

- **核心管理命令**：
  - `/mcp list`：列出所有配置的MCP服务器，查看运行状态、工具数量；
  - `/mcp enable/disable 服务器名称`：一键启用/禁用对应的MCP服务器；
  - `/mcp reconnect 服务器名称`：重连断开的MCP服务器，不用重启会话；
  - `/mcp add`：添加新的MCP服务器，支持stdio、HTTP、SSE三种传输方式。
- **隐藏优化技巧**：
  - 自动工具发现：当MCP服务器的工具太多，超过上下文10%的时候，Claude会自动启用MCPSearch工具，按需加载工具，不会全量加载到上下文，大幅节省token；
  - 重复数据删除：插件里的MCP服务器和手动配置的重复了，会自动跳过，避免出现重复的工具，减少上下文占用；
  - OAuth优化：最新版本已支持Client ID Metadata Document (CIMD / SEP-991)，还有手动URL粘贴回调，自动刷新token，不会出现token过期还要重新登录的问题。

## 九、环境诊断与自我优化：让Claude Code越用越懂你

遇到问题不用到处搜教程，这些命令能帮你自我诊断、自我优化，解决90%的环境问题，还能让Claude Code越用越贴合你的使用习惯。

### 1. /insights：你的使用习惯分析报告

这是被严重低估的一个命令，它会生成一份完整的HTML报告，深度分析你过去一个月使用Claude Code的所有习惯，包括：

- 你最常用的命令、工具、模型，高频的操作模式；
- 你的重复操作、低效行为，给出对应的优化建议，推荐自定义命令和Skill；
- 你的会话时长、token消耗、成功率，还有翻车现场记录（比如命令执行失败、代码回退的场景），给出规避建议；
- 自动内存优化建议，告诉你哪些内容应该存入持久化内存，减少重复解释。
- **最佳实践**：每个月跑一次`/insights`，它会让你重新认识自己的使用习惯，发现很多自己没注意到的低效操作，持续优化你的工作流。

### 2. /doctor：环境问题一键诊断修复

这是遇到问题第一个要跑的命令，堪称Claude Code的「电脑管家」，能一键诊断你的环境问题，给出具体的修复方案。

- **核心能力**：输入`/doctor`，Claude会全面检查你的环境，包括：
  - 配置文件的语法错误、无效配置、冲突项；
  - 权限规则里的无效规则、无法匹配的规则；
  - 插件的安装问题、依赖缺失、版本冲突；
  - MCP服务器的运行状态、连接问题、认证错误；
  - 网络连接、API认证、自动更新状态；
  - 终端兼容性、快捷键配置问题。
- **核心价值**：80%的环境问题，都能通过`/doctor`找到原因，并且拿到可直接执行的修复命令，不用到处搜教程、翻issue。

### 3. 其他常用诊断命令

- **/stats**：查看你的全量使用统计，包括最常用的模型、总token消耗、会话时长、最常用的工具/命令，支持按「最近7天」「最近30天」「全部时间」筛选，帮你了解自己的使用情况，优化成本；
- **/usage**：查看你的订阅额度使用情况，包括5小时、7天的速率限制，剩余的Opus额度，还有额度重置时间，避免写到一半被限速；
- **/debug**：一键开启/关闭debug日志，遇到网络问题、API报错、插件故障时，开启debug模式，能看到详细的请求和错误信息，方便排查问题；
- **/release-notes**：查看最新的更新日志，了解新增的功能、修复的bug，第一时间用上新特性。

## 十、CLI脚本化与CI/CD集成：把Claude Code嵌入你的工作流

Claude Code不止能在交互式终端里用，还能通过CLI命令，嵌入到你的shell脚本、CI/CD流程里，实现全自动化的代码审查、测试、部署、文档生成等工作。

### 1. 非交互模式（-p/--print）：脚本化的核心

- **基础用法**：`claude -p "你的prompt"`，直接执行prompt，输出结果，不用进入交互式终端，完美适配脚本场景。
  - 示例1：代码审查 `claude -p "审查当前git diff的代码改动，找出潜在的bug和安全问题" < <(git diff)`
  - 示例2：文档生成 `claude -p "给这个Python文件生成README文档" < main.py > README.md`
- **--bare 隐藏参数（脚本化神器）**：
  最新版本新增的`--bare`参数，和`-p`配合使用，会跳过hooks、LSP、插件同步、技能目录遍历，启动速度提升数倍，专门为脚本化、自动化场景设计。
  - 注意：`--bare`需要配置`ANTHROPIC_API_KEY`环境变量，禁用OAuth和钥匙串认证，同时禁用自动内存，保证执行的稳定性。
  - 示例：`claude --bare -p "给当前的PR生成变更日志" < <(git log main..HEAD)`
- **进阶参数**：
  - `--system-prompt-file 路径`：指定系统提示文件，给脚本化执行设置固定的规则和规范；
  - `--append-system-prompt-file 路径`：追加系统提示文件，在默认规则的基础上添加自定义规范；
  - `--output-format stream-json`：输出流式JSON格式，方便脚本解析执行结果。

### 2. CLI启动参数隐藏用法

这些启动参数，能让你在启动Claude Code的时候，就完成所有配置，不用进入终端再手动操作，完美适配自动化、团队统一配置的场景。
| 启动参数 | 核心功能 | 适用场景 |
|----------|----------|----------|
| `--name 会话名称` | 启动时直接给会话命名 | 方便后续恢复，团队项目统一会话命名规范 |
| `--model 模型名称` | 启动时指定模型，比如`opusplan`、`sonnet` | 固定脚本执行的模型，保证执行效果稳定 |
| `--effort 等级` | 启动时指定努力程度，low/medium/high | 简单任务用low，提升执行速度；复杂任务用high，保证效果 |
| `--worktree/-w` | 启动隔离的git工作树 | 自动化测试、实验性修改，不污染主分支 |
| `--resume 名称/ID/PR` | 启动时直接恢复指定会话 | 下班没干完的活，上班一键接着干 |
| `--settings 文件路径` | 指定自定义的settings.json文件 | 不同项目用不同的配置，团队统一配置文件 |
| `--mcp-config 文件路径` | 指定MCP配置文件 | 启动时自动加载对应的MCP服务器，不用手动配置 |
| `--add-dir 目录路径` | 添加额外的工作目录 | 让Claude访问项目外的公共组件库、配置文件 |

### 3. 自动化与CI/CD集成场景

- **PR自动代码审查**：在GitHub Actions、GitLab CI里，用claude -p --bare命令，读取PR的diff内容，自动生成代码审查报告，评论到PR里；
- **自动生成文档**：写个shell脚本，遍历项目里的所有代码文件，用Claude自动生成对应的接口文档、注释，提交到仓库里；
- **定时监控与报告**：结合系统crontab，用claude -p命令，定时拉取服务日志、监控数据，自动分析异常，生成日报/周报，发送到企业微信、Slack；
- **批量代码重构**：写个脚本，遍历项目里的所有符合条件的文件，用Claude批量执行代码重构，比如把JavaScript代码改写成TypeScript，统一代码规范。

### 4. 环境变量高级配置

通过这些环境变量，你可以深度定制Claude Code的行为，适配不同的环境和场景。
| 环境变量 | 核心功能 | 适用场景 |
|----------|----------|----------|
| `ANTHROPIC_API_KEY` | 指定API Key | 脚本化、非交互模式必备 |
| `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` | 禁用实验性beta特性 | 解决代理网关、Bedrock/Vertex的400报错 |
| `CLAUDE_CODE_SIMPLE` | 极简模式，禁用技能、内存、MCP、hooks | 简单任务、脚本化场景，启动更快，占用更低 |
| `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` | 禁用系统提示里的git相关指令 | 减少token占用，非git项目适用 |
| `CLAUDE_BASH_NO_LOGIN` | bash工具不使用登录shell | 提升命令执行速度，避免shell配置的干扰 |
| `ANTHROPIC_CUSTOM_MODEL_OPTION` | 给模型选择器添加自定义模型 | 自部署模型、第三方代理模型适配 |
| `CLAUDE_CODE_TMPDIR` | 自定义临时文件目录 | 适配受限的Linux环境、CI/CD环境 |

## 十一、新手避坑指南与高阶最佳实践

### 新手最容易踩的5个坑

1. **上来就让Claude写代码，不做规划**：复杂任务一定要先让Claude出计划，你确认后再执行，能减少80%的代码回退、需求跑偏，这是官方首推的最佳实践；
2. **上下文污染不处理**：临时问题、无关对话，一律用`/btw`处理，不要写入主会话历史，否则长会话很容易出现token溢出、Claude忘记核心需求的问题；
3. **全程用同一个模型**：简单的文件查询、语法修复用Haiku，速度快、成本低；架构设计、复杂bug修复用Opus，深度推理；日常开发用Sonnet，平衡效果和成本，不要全程用Opus浪费额度；
4. **不做持久化配置**：项目的规范、架构、常用命令，一定要写入CLAUDE.md、自定义Skill、自动内存里，不要每次都重复解释，Claude记不住不是它笨，是你没给它持久化的记忆；
5. **滥用bypassPermissions模式**：除非是完全信任的环境，否则绝对不要开启全量绕过权限的模式，一旦开启，Claude拥有和你一样的终端权限，存在高危风险。

### 高阶用户的7个最佳实践

1. **并行会话左右互搏**：开两个终端，一个会话写代码（Writer），一个会话做代码审查（Reviewer），写完一个模块，直接把diff丢给审查会话，左右互搏，代码质量直接翻倍；
2. **持续打磨CLAUDE.md**：每次踩坑、修正错误、确定新的规范后，都让Claude更新项目的CLAUDE.md，避免再犯同样的错误，让它越用越懂你的项目；
3. **沉淀可复用的Skill库**：凡是每天重复的操作，都封装成自定义Skill，比如代码审查、单元测试生成、部署上线、文档生成，一次封装，永久复用；
4. **多Agent分工协作**：复杂项目不要用单会话串行开发，拆分成不同的角色，用Agent Team并行开发，效率提升3-5倍；
5. **隔离工作树做实验**：所有不确定的方案、实验性的修改，一律用`--worktree`启动隔离会话，绝对不要在主分支上直接让Claude改代码，避免把仓库搞乱；
6. **用hooks固化工作流**：把你的开发流程、安全规范、自动化操作，都用hooks固化下来，比如PreToolUse钩子做安全校验，SessionEnd钩子自动备份会话、生成开发日志；
7. **定期优化使用习惯**：每个月跑一次`/insights`，分析自己的低效操作，优化配置、封装命令，让Claude Code越用越贴合你的工作流。

## 结尾

Claude Code的更新速度快到让人焦虑，但本质上，它的所有迭代，都是为了让你「更少的操作，完成更多的事」。不用追求把所有功能都用完，先挑1-2个能解决你当下痛点的技巧，明天就用起来——真正能改变你效率的，从来不是收藏了多少教程，而是把一个技巧用透。
